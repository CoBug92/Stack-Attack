# Инструкции для AI-агентов в StackAttack

## Область действия

Инструкции действуют для всего репозитория. StackAttack — нативная iOS-игра по мотивам классической игры Siemens, с интерфейсом SwiftUI и игровым полем SpriteKit.

Ограничивайте работу текущей задачей. Сохраняйте несвязанные пользовательские изменения и не откатывайте работу других агентов.

## Форматирование кода

- Для всех новых и редактируемых Swift-файлов используйте табы для отступов.
- Дефолтный шаг отступа: `tab == 4` колонки.
- Не делайте массовое переформатирование несвязанных файлов только ради приведения старого кода к этому правилу без отдельного запроса пользователя.
- File-local константы для Swift/SwiftUI выносите вниз файла в `private extension` соответствующего типа (`CGFloat`, `Double`, `String`, `LocalizedStringKey` и т.п.) по паттерну Compound Interest. Не вводите для этого обычных nested `Constants`/`Layout` enum, если речь не о действительно типизированной доменной группе значений.

## Временное обязательное ограничение

Пока пользователь приводит игру в порядок, **не запускайте Code Reviewer и Verifier** — ни как агентов, ни как независимые workflow. Конфигурации этих ролей подготовлены только на будущее.

Разрешены и ожидаются:

- целевые тесты, если существует подходящий test target;
- точечный или общий SwiftLint;
- неподписанная локальная сборка;
- ручной smoke-check изменённого сценария;
- self-review diff главным агентом.

Это временное правило имеет приоритет над общими маршрутами по риску до явного разрешения пользователя снова использовать Code Reviewer и Verifier.

## Работа над игровыми механиками

- Перед изменением поведения сверяйтесь с `docs/game-rules.md` и формулируйте наблюдаемые критерии приёмки.
- Разделяйте непрерывную физику и визуальную анимацию от логической сетки размещения ящиков. Не предполагайте, что отказ от пошагового движения означает полный отказ от дискретных правил заполнения рядов.
- Для составных вводов (например, прыжок плюс направление) явно определяйте временное окно, приоритет команд и поведение при удержании.
- Для игровых состояний (playing, paused, stunned и game over) задавайте допустимые переходы и блокировку ввода.
- Не добавляйте зависимости, инфраструктуру или широкий рефакторинг без необходимости для задачи.

## Проверка

Начинайте с самой узкой релевантной проверки и расширяйте её пропорционально риску.

Точечный lint:

```sh
swiftlint lint --config Scripts/swiftlint/.swiftlint.yml --no-cache <changed-swift-files>
```

Lint исходников приложения:

```sh
Scripts/swiftlint/swiftlint.sh
```

Генерация Xcode-проекта после изменения `project.yml` или структуры исходников:

```sh
Scripts/generate.sh
```

Неподписанная сборка:

```sh
xcodebuild \
  -project StackAttack.xcodeproj \
  -scheme StackAttack \
  -destination "generic/platform=iOS Simulator" \
  CODE_SIGNING_ALLOWED=NO \
  build
```

Не называйте пройденными проверки или игровые сценарии, которые фактически не запускались.
